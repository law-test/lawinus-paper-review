# 공통 본문·각주 편집

원본 PDF/HWP는 보존한다. 웹 공통 편집은 등록된 기준본의 문단·각주 식별자에 연결하며, 모든 방문자가 같은 수정 내용을 읽는다. 저장할 때 기존 익명 세션을 사용한다. 방문자 누구나 다른 방문자의 수정 내용을 다시 고칠 수 있다. 개인 메모의 공개 범위와 소유권은 변경하지 않는다.

원문은 수정 0이다. 저장할 때 현재 수정 번호와 맞지 않으면 충돌을 알리고 저장하지 않는다. 복원은 선택한 내용을 새로운 수정으로 추가한다. 원문이나 과거 이력을 덮어쓰거나 삭제하는 공개 API는 없다. 공개 이력에는 방문자 표시명만 포함하고 인증 계정 UUID는 제외한다.

## 논문 파일에 반영하기

`scripts/export-shared-edits.mjs`를 실행하면 지정 기준 시점의 모든 이력을 `all-revisions.json`으로, 각 항목의 최종 내용을 PDF 쪽수순 Before/After/상세이유 목록으로 저장한다. 기본 경로는 `work/shared-edits-export-시각/`이다. 기존 파일은 덮어쓰지 않는다. 사이트의 내보내기 기능도 모든 원문과 이력을 수집한다.

1. 내보낸 기준본 ID와 원본 PDF/HWP 해시를 현재 인간 기준본과 대조한다.
2. 문단·각주 식별자와 원문 해시를 확인한다. 서로 다른 기준본의 같은 숫자 식별자를 합치지 않는다.
3. 방문자가 남긴 수정 이유와 근거 자료를 검토한다. 새 판례·문헌·인용면은 원문 대조 후 채택 여부를 판단한다. 웹에 저장됐다는 사실을 법리·인용 검증으로 취급하지 않는다.
4. 채택한 최종 문안으로 PDF 쪽수순 수정지시서를 갱신하고, 기존 원본을 보존한 새 적용 HWPX를 만든다. 복원 이력도 남긴다.
5. 적용 결과에 내보낸 snapshotId와 최종 revision을 기록한다. 내보낸 뒤 생긴 수정은 다음 반영 때 검토하며 이미 적용됐다고 표시하지 않는다.

각주 내용을 수정해도 기존 문헌 연결·인용면 좌표가 자동으로 바뀌지는 않는다. 인용 출처를 바꾼 수정은 문헌 연결을 별도로 검증·갱신한다. 웹 공통 텍스트를 원본 PDF 자체가 변경된 것으로 표시하지 않는다.

## 수정지시서에서 문안 가져오기

`scripts/sync-revision-proposals.py`는 `--guide`, `--patches`, `--baseline`, `--note-map`, `--version`, `--evidence`를 받는다. 현재 인간 원본과 독립 해시 목록을 대조한 뒤 표시용 `after`와 저장용 `applyText`를 구분한다. `after`는 지시서 그대로 보존하며, 저장에 쓰는 문안은 원본 문단·각주 식별자를 유지한 수정자료에서 생성한다. UI는 `after`를 저장용 문안의 대체값으로 사용하지 않는다.

삭제의 `applyText`는 빈 문자열이다. 삽입만 있는 변경은 기존 문단 전체와 추가 문단을 함께 포함한다. 기존 각주 표지는 `[^인간원본번호]`, 재인용은 인간 원본의 각주번호를 유지한다. 조판 지시를 문안에 섞지 않으며, 새로운 각주 등록이나 전체 목차·참고문헌 재편이 필요한 변경에는 `applyText`를 주지 않고 `applyUnsupportedReason`으로 안내한다. 자동으로 기존 번호를 새 각주에 배정하지 않는다.

Python 검사는 `python -m unittest discover -s tests -p test_revision_proposals.py`로 실행한다. 공개 데이터의 원본 대응·삭제·각주 재인용 회귀 검사는 `node --test tests/revision-proposals.test.mjs`로 실행한다. 모두 문안 변환 검사이며 실제 공통 본문을 저장하지 않는다.

## 저장과 검사

원문·현재 번호·추가 전용 수정 이력은 외부에 노출하지 않는 `paper_review_private` 스키마에 저장한다. 공개 RPC는 invoker이고, 검증된 내부 함수만 권한을 가진다. 직접 테이블 접근을 막기 위해 RLS와 권한 회수를 함께 사용한다. 원문 등록 함수는 관리자만 실행할 수 있다. 개별 문안 100,000자, 수정 이유 2,000자, 방문자당 5분에 60건 제한이다.

전체 내보내기는 첫 조회 시점의 고정 번호까지 페이지별로 수집하며 수량·중복·해시·이력 연결을 확인한다. 영구 원문과 이력은 삭제하지 않으며 독립 시험 데이터는 트랜잭션을 되돌려 정리한다.

`shared-edits-postgres.test.mjs`는 실제 PostgreSQL WASM에서 권한·수정·복원·충돌·전체 수집을 검증한다. 이는 실제 Supabase Auth나 브라우저 검수와 구별된다. `supabase/shared-edit-verification.sql`은 실제 서버의 별도 시험 기준본에서 같은 핵심 조건을 확인한 뒤 모든 시험 변경을 되돌린다.

보안 검사에서 새 내부 테이블의 ‘RLS 활성화·정책 없음’은 직접 접근을 허용하지 않기 위한 의도된 상태다. 기존 개인 메모용 public definer RPC와 비밀번호 보호 경고는 이번 공통 편집에 새로 도입한 항목이 아니다. 비밀번호 로그인 화면은 사용하지 않는다.
